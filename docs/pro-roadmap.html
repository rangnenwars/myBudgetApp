A

Reference research — Ramsey Solutions

Pulled from ramseysolutions.com to sanity-check the feature direction against a well-known budgeting product (EveryDollar) before committing to a build list.

EveryDollar runs on zero-based budgeting — plan every dollar before spending, income minus expenses equals zero. Free tier covers manual entry, categories, bill reminders. Premium ($79.99/yr) adds bank sync, custom spending reports, a "financial roadmap," projected net worth, a debt tracker, and live coaching.

Their debt tracker runs the debt snowball method: order debts smallest-balance-first regardless of interest rate, pay minimums on the rest, throw every spare rupee at the smallest, then roll that payment into the next-smallest once it clears. They also document debt avalanche (highest-interest-first) as the mathematically optimal alternative — but say snowball wins in practice because of momentum.

Why bank sync stays out

It needs a paid third-party data aggregator plus a real backend to hold bank credentials/tokens — and it means handling real financial credentials, which this project shouldn't do without a much bigger security review than a personal-project scope warrants.

C

User data & session design

With no backend, there's no administrator overseeing multiple people — each device/browser holds its own isolated data. "Administer users" here means local account & data management, not a multi-tenant admin portal.

Gap found while designing this

The current schema's transactions, loans, investments, and savings_goals tables have no user_id column — they're global to the device, not per-account. Fine for a single tester, but a second local account on the same device would see the first account's data today. Needs fixing before Pro features (especially net worth history and reports) get built on top of it.

Proposed "Account & Data" screen — not built yet

  • Profile — edit name/email
  • Switch account — pick between local accounts on this device (still requires the password)
  • Export all data — full JSON backup for this account
  • Import / restore — load a previous backup
  • Reset app data — wipe this account's data, with confirmation
  • Delete account — removes the account row and all associated data
  • App lock — toggle PIN/biometric requirement

Session design

Today a session is just {"{ userId }"} in AsyncStorage — checked on launch, cleared on logout, no expiry. Proposal: keep it that way by default (this isn't a shared-device use case), and let App lock be the real security boundary — Face ID / fingerprint / PIN after N minutes backgrounded, independent of the session itself. That's how most personal finance apps (including EveryDollar) actually handle it: you stay logged in, the app re-locks itself. Real JWT expiry/refresh, per the original spec, only becomes necessary once cloud sync (B2.8) exists and a session represents trust with a remote server.

D

Reporting module

The direct answer to "summary dashboard and data trends on demand." A new Reports tab, Pro-gated, separate from the existing Dashboard (which stays as the free, current-month-only snapshot).

  • Time range picker — this month / last 3 / last 6 / this year / all time / custom
  • Summary row — income, expense, net savings, savings rate %, net worth for the range
  • Trend chart — line chart, selectable metric, per month across the range — where react-native-chart-kit (already installed, currently unused) finally earns its place
  • Category breakdown — donut + ranked list with month-over-month delta arrows
  • Debt payoff progress — outstanding balance trending down per loan
  • Goal progress overview — all goals' % complete, side by side
  • Export — "download this report as CSV" (ties into B1.6)

New data-layer functions needed

All computed live from local data on demand — nothing pre-materialized except the net worth snapshot, which is a point-in-time figure that can't be derived retroactively once loan/investment values change.

  • getRangeSummary(startMonth, startYear, endMonth, endYear)
  • getMonthlySeriesForRange(...) — one row per month, for charting
  • getCategoryBreakdownForRange(...) — range version of the existing month-only query
  • recordNetWorthSnapshot() — called on Dashboard/Reports focus, writes one row/month to a new net_worth_snapshots table
